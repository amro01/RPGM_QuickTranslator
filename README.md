# QuickTranslator

> 给 RPG Maker MV / MZ 用的 **19 KB 离线字典汉化加载器**。
> 无外部注入、无后台常驻进程、无修改器、可一键还原。

`QuickTranslator` 把一份 `{ "日文原文": "中文译文" }` 的 JSON 字典，直接挂载进游戏运行时的文本管线。翻译发生在引擎解析控制符**之前**，所以 `\N[1]`（人名）、`\C[18]`（颜色）、`\SP[normal]`（立绘表情）全部原样保留 —— 汉化之后，红色的重点字依然是红色。

整套方案只有 5 个文件、18.8 KB，不需要安装运行时、不需要联网、不需要管理员权限。

## 为什么需要它

RPG Maker MV/MZ 的文本在运行时由 `Window_Base.drawTextEx` 逐行绘制，控制符（`\C[x]`、`\N[x]`、`\V[x]` …）在绘制前才被 `convertEscapeCharacters` 展开。市面上常见的做法是用外部工具注入进程、挂载翻译层，代价是：

- 工具本体接近 1 GB，附带修改器与一堆用不到的功能；
- 常驻后台进程，启动慢、占用内存；
- 改的是游戏目录里的文件，卸载后容易留下残留；
- 译文层在控制符展开**之后**才介入，句子里一有颜色标签就整句失配。

`QuickTranslator` 反过来做：只挂 5 个极薄的函数钩子，在控制符展开前查一次哈希表，命中就换字符串。没有注入、没有网络、没有常驻，卸载时把两行 `plugins.js` 改回去即可。

## 核心特性

| 特性 | 说明 |
| --- | --- |
| 极小体积 | 全部 5 个文件合计 19,286 字节（约 18.8 KB） |
| 零依赖 | 只用 NW.js 内置的 `fs` / `path`，不引任何第三方库 |
| 零常驻 | 没有后台进程、托盘、守护服务；翻译只在渲染那一瞬间发生 |
| 完全离线 | 不发任何网络请求；字典就是本地 JSON |
| 可逆 | 安装时自动备份 `plugins.js`，卸载脚本原样还原 |
| 控制符零损失 | 颜色、人名、变量、立绘表情标签逐字节保留 |
| 三级降级匹配 | 整句 → 剥离头部标签 → 按控制符分段，专治 MTool 碎片化字典 |
| 状态级替换 | 在写入游戏状态时就翻译，MZ 名字框/选项框按中文字宽重新测宽，不截断 |
| 智能收集遗漏 | 只收含日文的句子，800 ms 去抖落盘，关窗前强制刷写 |
| MV / MZ 双引擎 | 自动识别 `www/js/plugins.js` 与 `js/plugins.js` |

性能上：命中的句子只做 **一次哈希查找**；只有未命中的句子才会走正则与分段逻辑。内存开销只有字典本身（几万条通常也就几 MB），没有纹理、没有进程。

## 30 秒上手（小白拖拽版）

### 前置条件

- Windows 10 / 11；
- 游戏是 **RPG Maker MV 或 MZ 的 Windows 桌面版**（目录里有 `Game.exe`，MV 还有 `www\` 文件夹）；
- 游戏目录可写（**不要**放在 `C:\Program Files` 下）；
- 已有一份 UTF-8 编码的翻译字典 JSON（MTool 导出的字典也能直接用）。

### 三步安装

1. **解压到游戏根目录**
   把仓库里这 5 个文件放到 `Game.exe` **同一层**：

   ```text
   MyGame\
   ├─ Game.exe
   ├─ QuickTranslator.js
   ├─ install.ps1
   ├─ uninstall.ps1
   ├─ 安装汉化(把json拖我身上).bat
   └─ 一键卸载.bat
   ```

2. **把字典 JSON 拖到 `安装汉化(把json拖我身上).bat` 上松手**
   脚本会自动完成：

   ```text
   [1/5] 定位游戏根目录
   [2/5] 检查 QuickTranslator.js
   [3/5] 识别引擎版本（MV: www\js\plugins.js / MZ: js\plugins.js）
   [4/5] 选定字典 JSON
   [5/5] 部署插件与字典，并把配置写进 plugins.js（原文件自动备份）
   >>> Done! Launch Game.exe to play! <<<
   ```

3. **启动 `Game.exe`**
   界面变成中文即成功。

> 忘记拖拽？直接双击 bat 也行：脚本会在游戏根目录里自动寻找第一个 `.json`（排除 `package.json` / `dict.json` / `missing.json`）。
> 架构图与文件流转说明见 [`PITFALLS.md`](PITFALLS.md) 第 2、5 节。

### 安装器到底动了什么

- 把 `QuickTranslator.js` 复制进插件目录；
- 把字典复制为 `dict.json`（游戏根目录、`www\`（MV）、插件目录各一份，保证插件在任何路径解析顺序下都能找到）；
- 在 `plugins.js` 的 `$plugins` 数组**开头**插入一条 `{"name":"QuickTranslator","status":true,...}`；
- 首次安装生成 `plugins.js.bak`，卸载时用它还原。

字典加载成功后，NW.js 开发者工具 Console 会打印：

```text
[QuickTranslator] 字典已加载: <路径> (N 条)
```

## 字典格式

顶层必须是 JSON 对象，**键 = 游戏里的原始日文（可以带控制符）**，**值 = 译文**：

```json
{
  "勇者よ、よくぞ参った。": "勇者啊，你终于来了。",
  "\\C[18]魔王\\C[0]が復活した！": "\\C[18]魔王\\C[0]复活了！",
  "手に入れた！": "获得了！"
}
```

注意事项：

- 文件必须是 **UTF-8**（有无 BOM 均可，插件会剥掉 BOM）；
- 值为空字符串 `""` 的条目按“未翻译”处理，**不会**把界面文字刷没；
- 键可以带 `\C[x]` / `\N[x]` / `\SP[...]`，也可以只写纯文本 —— 匹配有三层降级，见下节；
- 条目数以万计也没问题：加载时一次性建表，运行时是哈希查找。

### 匹配规则与兼容性

1. **整句精确匹配**：`dict[原文]` 命中直接用。
2. **剥离头部标签匹配**：原文形如 `\SP[normal]\C[2]よくぞ参った。`，先剥掉头部连续的控制标签，用主体去查，命中后把标签原样拼回。
3. **按内嵌控制符分段**：句子中间夹着 `\c[18]` 之类标签时，用 `\\[A-Za-z]+(?:\[[^\]]*\])?` 切分，**标签原样保留**，纯文字段逐段查表后拼合。MTool 把一句话按颜色标签切碎存储的情况，靠这一层救回来。

只要任一段命中，整句就不再进 `missing.json`。因此：

- 颜色标签、字体高亮、人名变量、立绘表情 **100% 保留**；
- 如果字典只翻了半句，未覆盖的那半句会保持日文原文（不会被吞掉）；
- 极个别插件不走 `drawTextEx` / `drawText` 而自绘文字（例如直接操作位图），不在覆盖范围内。

## 补翻译：`missing.json` 工作流

字典没命中的句子会被收集到 `dict.json` **同目录**下的 `missing.json`：

```json
{
  "まだ見ぬ世界へ": "",
  "\\C[6]宝箱\\C[0]を開けた": ""
}
```

- 只收集**含日文字符**的文本，纯数字、纯英文、`\V[12]` 这类纯控制符会被过滤；
- 写入有 **800 ms 去抖**，不会每句都落盘；关闭游戏窗口时（`beforeunload`）强制同步刷写，不会丢；
- 已翻译过的文本自动从旧 `missing.json` 里清掉；
- 补完后把内容并入 `dict.json` 的译文值，重新拖拽 bat 安装（或直接把新字典放进 `js/plugins/`）即可。

实测高速跳过对话时，收集器也不会卡顿：`Set` 去重 + 定时合并写。

## 卸载

双击 **`一键卸载.bat`**：

1. 若存在 `plugins.js.bak`，直接还原（最干净）；
2. 否则逐行剔除包含 `QuickTranslator` 的配置行（不会误伤其他插件的大括号/数组参数）；
3. 删除注入的 `QuickTranslator.js`、各份 `dict.json`、`missing.json`；
4. 游戏回到原版日文。

> 卸载脚本只会清理**注入产物**（游戏根目录、MV 的 `www\`、插件目录下的 `dict.json`）。因此请**不要把唯一的字典副本放进这三处并命名为 `dict.json`** —— 建议源字典另存为 `MyGame_译文_v1.json` 之类，再拖给安装器，原文件不会被碰。

## 常见问题

**Q：启动后还是日文？**
依次检查：`plugins.js` 里是否有 `QuickTranslator` 且 `"status":true`；`js/plugins/`（MV 为 `www/js/plugins/`）下是否有 `dict.json`；JSON 是否为合法 UTF-8；是否被其它文本类插件覆盖了钩子。打开开发者工具 Console 看 `[QuickTranslator]` 日志最直接。

**Q：只有一部分句子变成中文？**
字典缺该句，或 MTool 字典把句子按颜色标签切碎了。跑一遍游戏，看 `missing.json`，补齐后重新安装。分段匹配已覆盖“整句带标签”的情况，但字典里**完全没有**的纯文字段无法凭空翻译。

**Q：文字被截断 / 选项框太窄？**
本插件在**游戏状态层**（`setChoices`、`setSpeakerName`）就替换文本，MZ 会按中文字宽重新测量。若仍截断，多半是原版插件把宽度写死了，或字体缺字导致回退字体更宽 —— 换一款包含中文字形的字体即可。

**Q：会写坏存档吗？**
不会。插件只改运行期字符串，绝不写入存档；文件侧也只读写 `dict.json` / `missing.json`。

**Q：手机版 / 网页版能用吗？**
不能。方案依赖 NW.js 的 `require`/`fs`，纯浏览器打开的 `index.html` 会因缺少 Node 环境而自动停用（有显式检测）。

**Q：能用在 Steam 版游戏上吗？**
只要游戏是标准 MV/MZ NW.js 打包、目录可写即可。请自行确认修改游戏文件是否符合平台条款。

**Q：换字典要重装吗？**
把新 JSON 再拖到安装 bat 上即可，会覆盖三处 `dict.json`。插件目录里的那一份优先级最高，手动只改根目录那份可能不生效。
